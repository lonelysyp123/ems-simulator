# 仿真模拟器 — 系统设计说明

## 1. 项目目标

- **仿真范围**：储能与光伏端到端仿真——多路电池堆（Rack）、多台 PCS、光伏单元（组串逆变器 + 箱变）、主/单元断路器、主变/单元变、计划负载；通过 **Modbus TCP** 与可选 **IEC 61850（MMS 服务端 + GOOSE 订户）** 对外联调。可组储能、光储或纯光伏工程。
- **可扩展性**：点位映射（CSV）+ `appsettings.json` 参数化；`DataExchange` 点目录驱动遥测/控制；支持多单元拓扑扩展。
- **对外名称**：仿真模拟器；工程名：EssSimulator。

## 2. 技术栈

| 类别 | 选型 | 用途 |
|------|------|------|
| 运行时 | .NET 8 | 主程序、自包含发布 |
| 宿主 | ASP.NET Core + `IHostedService` | Web、后台仿真、协议服务 |
| 前端 | Vue 3 + Element Plus + Vite | 浏览器操作界面（`Web/src/`） |
| 实时 | SignalR | 主接线/电池/日志/IEC 61850 报文推送 |
| 协议 | NModbus 3.x | Modbus TCP 从站 |
| 协议 | libiec61850（P/Invoke） | IEC 61850 MMS IED + 入向 GOOSE 订阅 |
| 配置 | `appsettings.json` + CSV / ICD | 拓扑、电气参数、Modbus / IEC 61850 映射 |
| 日志 | log4net | 文件/控制台日志 |
| CSV | CsvHelper | 点表加载 |
| 测试 | xUnit | `EssSimulator.Tests/` |

## 3. 架构总览

```
┌─────────────────────────────────────────────────────────────┐
│  协议层：ModbusSimServer / DataExchangeSession              │
│  IEC 61850：Iec61850LayerManager（MMS IED + GOOSE 订户）    │
│  LC：LocalControl/（可选；standard 点名桥接，中压表 ModelSim→simLc Modbus）│
│  映射层：EssSimModelApi (PcsMapper, BmsMapper, EmMapper)    │
│  光伏：ModelSim 直绑 PvUnitDevice（Logger / 电表，无独立 Mapper）│
└───────────────────────────┬─────────────────────────────────┘
                            │ 对象路径 / ControlEffect
┌───────────────────────────▼─────────────────────────────────┐
│  编排层：EnergyStorageSystem（Host 时钟）+ PlantEngine.Step        │
│  传播层：ElectricalNetwork + RadialPowerSweepEngine（生产主路径）   │
│  热/耦合：PlantThermalSystem + PlantCouplingGraph（PCS↔BMS）        │
│  夹具：NetworkSolver（仅单测，不参与生产步进）                      │
│  桥接层：NetworkControlBridge                                      │
└───────────────────────────┬─────────────────────────────────┘
                            │ 共用设备实例
┌───────────────────────────▼─────────────────────────────────┐
│  设备层 EssDeviceSimModel/Devices/* + Pv/*                    │
│  PcsDevice · TransformerDevice · BreakerSimulator             │
│  GridSimulator · LoadDevice · MeterSimulator · BmsRackDevice  │
│  PvUnitDevice（逆变器 / 组件 / 方阵气候 / Logger）            │
└─────────────────────────────────────────────────────────────┘
```

### 3.1 设备模型

| 设备 | 说明 |
|------|------|
| `PcsDevice` | 有功/无功爬坡、并网/离网、黑启动 V/f、直流/交流换算、保护 |
| `TransformerDevice` | 一二次电压/电流、铁损铜损、励磁涌流 |
| `BreakerSimulator` | 主断/单元断合分，网络控制面 SSOT |
| `GridSimulator` | PCC 无功—电压反馈 |
| `LoadDevice` | 35 kV 负载计划功率 |
| `BmsRackDevice` | BMS Rack 与 DC 端口、保护评估、并网链路 |
| `BatteryRackSimulator` | 电芯/簇/堆物理（`EssDeviceSimModel/Battery/`） |
| `PvUnitDevice` | 光伏 MVS 箱变站：组串逆变器 + Logger/低压电表/气象/PID（`EssDeviceSimModel/Pv/`） |
| `PvInverterDevice` | 单向逆变器：MPPT、限发、效率；只向电网送电 |
| `PvModuleSimulator` | 组件 IV / 辐照 / 温度 / 双面反照率 / 年限衰减 |
| `PvArrayClimate` | 方阵 A/B 独立气候（环境温度、入射角、反照率） |

光伏单元由组态模板 `pv_unit` 或 overlay `PvUnits` 展开（根 `appsettings.json` 通常无此节；纯光伏工程 `EffectiveEssUnitCount=0`，不伪造 BMS/PCS）。
每单元默认 16 台 320 kW 逆变器、组件目录 `TrinaPvModuleCatalog`（未知型号校验 `PV_UNKNOWN_MODULE`）。
`PlantEngine.Step` 先 `StepPvUnits` 再径向潮流：光伏出力作为 35 kV 馈线注入。
协议：`simPvN`（`pv_logger.csv`）+ `simPvMeterN`（`pv_apm810.csv`）；点表 `ModelSim` 绑 `pvDeviceId.Logger.*` 等，无独立 Mapper。
内部控制 `esscmd setpvN` / 主接线按钮走 `DeviceControlFacade`，与 EMS 写 Modbus 同源。

### 3.2 EMU 虚拟模型与 PCS 通用化

- **PCS 是仿真设备模型**：`PcsDevice` 为物理实体；`PcsData` DTO 分层为
  核心区（各厂家都有的电气量/功率/状态/启停命令，与现有点表 100% 兼容）+
  通用告警框架 + 扩展区：
  - `CustomAlarmWords` + `SetAlarmBit/GetAlarmWord`：字 0~6 对应 `AlarmSummary1~7`，
    字 ≥7 为厂家自定义告警字；新厂家点表无需再追加大量 bool 字段。
  - `ExtraAnalogValues[16]` / `ExtraDigitalValues[16]`：按数字索引的遥测/遥信扩展槽，
    反射可绑 `emuN.PcsList[i].ExtraAnalogValues[j]`（反射解析器仅支持整型索引器，
    故不用字典形式）。
- **EMU 是虚拟聚合模型**：每个储能单元对应 1 个 EMU，聚合 N 台 PCS
  （每单元台数可配置，未配置默认 2 台，默认回归路径行为不变）。
  远程集中控制生效时（syst4=1 且 syst5=1），`EmuPowerDispatcher` 将 EMU 级
  目标有功/无功（syst1010/syst1011）按台数简单均分写入各 PCS 功率设定，
  限幅由 `PcsDevice.SetPowerCommand` 兜底；本地模式保留单 PCS 点位直写。
  - `syst6` 系统操作（边沿生效）：3 启动→全部开机；4 停止→全部停机；
    5 待机→保持运行但目标清零；6 重置→停机（启停写 0 自动清除故障锁存）。
  - `syst7` 黑启动模式批量写入→各 PCS `BlackStartEnabled`（安全联锁仍由
    `ApplyEmuCommands` 把关）。
  - `MapEmuState` 同步补齐 EMU 统计字段（PCS 总数/在线/并网/告警/故障台数、
    禁充禁放 All/Any 标志）。
- **EMU 设备树分层构成（协议聚合视图）**：EMU/LC 不参与电气求解，仅采集数据与
  派发控制。`EssUnitConfig.Groups`（`EmuGroupConfig`：组内 PCS/BMS 按位对齐、
  可选组级断路器/电表名称）表达「EMU → group → PCS 支路」场站差异（EMU=2 支路 /
  EMU=2 group×2~4 支路）；`Groups` 为空时保持扁平构成，完全向后兼容。
  - `PcsDataServer.BuildEmuMirror` 按机组构建设备树：`Groups[g].PcsList[i]` 与扁平
    `PcsList[k]` 持有**同一 PcsData 实例引用**，两条路径读写同一对象，控制效果层
    （`EmuPcsControlEffect` 按机组解析）零改动；每机组固定建 1 台单元变镜像
    （`Transformers[0]`）。
  - 镜像刷新（`PcsEmuSynchronizer.SyncDeviceMirrors`）：变压器镜像优先抄电气层
    单元变真实值（功率/负载率/油温），缺失时按组内 PCS 求和兜底合成；EMU 级
    断路器镜像跟随 `Emu.PowerOnOff`；组级断路器为纯协议镜像恒合闸，不产生电气动作。
  - 组聚合遥测（`MapGroupState`）：组内 PCS 求和 P/Q 与台数统计写入 `EmuGroupData`。
  - 点表门控（`EmuDeviceCatalogFilter`）：新路径 `Groups[g].PcsList[i]` /
    `Groups[g].Breaker` / `Transformers[k]`（本期仅 k=0）/ `Breaker.*` 按机组构成门控；
    组内 PCS 启停/功率点位与扁平路径同控制效果（`InferEffectId` 子串匹配天然兼容）。
  - 电气层不变：每 EMU 仍 1 台单元变 + 至多 1 台单元高压断路器；EMU 级目标均分
    派发范围仍为全机组；组级目标派发为后续扩展。
- **通道↔单元映射**：统一走 `EnergyStorageSystem.UnitIndexOfPcs/PcsBaseIndexOfUnit`
  与静态布局辅助 `PcsUnitLayout`，各层（求解器、GUI/Web、命令、Droop 切片）不再
  自行 `*2`/`/2` 槽位推算。基础 LC 聚合协议仍按每 EMU 的 PCS 组抄数；拼装 LC 的
  `unit_5.5MW` / `unit_10MW` 片段始终共存（`n`=PCS 组号，模块=支路），不走点名槽位选型。
- **组态编辑同构**（`Web/Topology/`）：EMU 模板为虚拟模板（`IsVirtual`，无端口、
  不可连线、画布不渲染），由侧栏「EMU 储能单元」列表管理，仅承载单元变参数；
  选中 EMU / EMU 分组时属性面板额外展示已绑定设备清单（单元级/组级分行，可点击跳转）；
  PCS 为独立模板「PCS 变流器支路」（上三相 AC、下 dc_pos/dc_neg；两条支路组成一台 PCS），参数 `emuId`（`emu_select` 下拉）
  关联所属 EMU；断路器 / 电表 / 变压器同样经可选 `emuId` 归入（单元级断路器/电表各至多 1 台，
  校验 `EMU_BREAKER_DUPLICATE` / `EMU_METER_DUPLICATE`；变压器不限台数）。
  保存校验要求每条 PCS 支路的 `emuId` 指向工程内存在的 EMU
  （`PCS_EMU_UNASSIGNED`），且至少一个含 PCS 的 EMU 或光伏单元（`NO_GENERATION_UNIT`）；
  光伏单元 `moduleModel` 须在组件目录内（`PV_UNKNOWN_MODULE`）。
  `TopologyRuntimeConverter` 按 `emuId` 分组生成 `EssUnitConfig`：PCS 列表按画布
  坐标排序，BMS 沿每台 PCS 的 DC 连线（直连或经 dc_bus）查找并去重后按位对齐，
  缺位用默认配置补齐；无 PCS 归入的 EMU 跳过并记入 Notes。
  `TopologyScaffold` 每个 EMU 生成 1 虚拟 EMU + 2 PCS + DC 母线 + 2 BMS，
  PCS AC 接 35 kV 母线、DC 经 DC 母线接 BMS。旧版 emu 复合节点工程不兼容、不迁移。
  分层构成由 `emu_group` 虚拟模板建模（参数 `emuId`），PCS / 断路器 / 电表 / 变压器经可选参数
  `groupId`（`group_select` 下拉，仅列同 EMU 分组）归入分组；保存校验追加
  `GROUP_UNASSIGNED` / `GROUP_EMU_MISMATCH` / `EMU_GROUP_BREAKER_DUPLICATE`
  （分组下断路器至多 1 台，电表/变压器不限台数），无分组的工程全部规则退化通过；
  `TopologyRuntimeConverter` 在 EMU 内含分组节点时按 `groupId` 归集生成 `unit.Groups`
  （未选组 PCS 归入合成「直挂」组），无分组时保持扁平转换逻辑。

### 3.3 关键设计原则

- **单一实例**：`ess._pcsList`、变压器、断路器与 `ElectricalNetwork` 内设备为同一对象。
- **电气主路径**：每 tick 先 `StepPvUnits` 更新光伏出力，再由 `RadialPowerSweepEngine.SolveCycle` 驱动 AC 段；PCS 物理在 `PcsDevice.Update` 完成 DC 耦合。`NetworkSolver` 仅作单测夹具。
- **控制面**：断路器、负载计划、BMS 链路等经 `NetworkControlBridge` 写入网络。
- **BMS 保护**：`BmsRackProtection` 簇级三级告警状态机；堆级 `SystemAlarms` 可经 Modbus 读写。

## 4. 数据流与线程

### 4.1 仿真主循环（`EnergyStorageSystem`）

固定步长（`PropagationIntervalMs`，默认 100 ms）：

1. `PlantEngine.Step` — **光伏出力** → 电气潮流 → 热网络 → PCS/BMS 耦合
2. `RadialPowerSweepEngine.SolveCycle` — 径向潮流与网侧回写（含光伏馈线注入）
3. Mapper / DataExchange 独立周期刷新 DTO 与寄存器

操作界面为浏览器（见 [B/S 架构说明](./B-S架构说明.md)），与仿真同进程。组态工程可生成 `configs/topology/generated/runtime-overlay.json`，工程模式启动时覆盖 `EssUnits`、`PvUnits` 等节。

### 4.2 Modbus 数据交换（`DataExchangeSession`）

适用于 **simEmu\*** / **simBms\*** / **simEm** / **simPv\*** / **simPvMeter\***：

| 管道 | 方向 | 说明 |
|------|------|------|
| 遥测 | 模型 → Modbus | 周期读 DTO，变更才写（Shadow 去重） |
| 控制 | Modbus → 模型 | FC5/6/16；`ControlEffect` 触发启停、黑启动、BMS 链路等 |
| 反馈 | 模型 → Modbus | 控制线圈/寄存器状态回写 |

**重连**：`link on` 后清空遥测 Shadow 并全量刷新，避免寄存器重建后读数为 0。

**接入 ACL**：`ModbusPortHub` 在 TCP Accept 时按 `configs/modbus-allowlist.json` 过滤来源 IP；空名单不限制，改名单需重启进程。

### 4.3 电气传播

`PlantEngine` 每拍先 `StepPvUnits`，再调用 `RadialPowerSweepEngine`：叶子（PCS / 光伏馈线）汇报 P/Q → 690V/35kV 汇总 → Grid Q-U → Coupler 传播 → 由 P/Q+V 算电流。`NetworkSolver` 仅保留为单测夹具，不参与生产步进。

黑启动 PCS 作为 `BUS_690` 本地电压源（`IBusVoltageSource`）。

## 5. 配置与点表

- **点表 CSV**：`Address` / `FunctionCode` / `ParamName` / `Scale` / `ModelSim` / `Type`
- **运行配置**：`appsettings.json` — 见 [appsettings 字段说明](./appsettings.explained.md)
- **每单元 PCS 台数**：`Simulator.EssUnits[].Pcs` 列表长度即该单元 PCS 台数
  （BMS 与 PCS 通道 1:1）；`Pcs` 为空默认 2 台（向后兼容）。
  PCS/BMS 通道总数 = 各单元台数之和（`SimulatorConfig.UnitCount`）。
- **设备工厂**：`PcsDeviceFactory`、`TransformerDeviceFactory` 等
- **点表解析链路**（`PointMapPathResolver`）：运行时按固定文件名（`emu.csv` / `em.csv` /
  `bms_bank.csv` / `bms_rack.csv` / `lc.csv` / `pv_logger.csv` / `pv_apm810.csv`）解析，优先级：
  1. **设备型号选型**：`pointmaps/models/{设备类型}/{型号}/` 下选中型号的点表
     （`DeviceModelRegistry` 扫描目录；选型持久化于 `configs/topology/device-models.json`，
     Web 系统配置页切换，重启生效）
  2. `pointmaps/models/{设备类型}/standard/`（未选型时的兜底）

EMU 型号仅 `standard`（单元 PCS 直控）。中压 LC 由互补片段拼装，挂在 `simLc*`；
`unit_5.5MW` 与 `unit_10MW` 始终共存（不是按支路数选型），`LcPointMapAutoSelect` 不再改 LC 选型。

`ModelSim` 列含义：

- `model=4|arg1=...`：绑定仿真 DTO 路径，遥测由模型刷新，控制可走 DataExchange。
- `model=sum|arg1=<路径A>|arg2=<路径B>`：遥测值 = 路径A + 路径B（只读，仅 FC3/4；缺失/非数值操作数按 0）。arg1 另支持分号分隔多路径（`arg1=<路径1>;<路径2>;...`）用于多机组系统级聚合。
- `model=max|arg1=<路径A>|arg2=<路径B>`：遥测值 = 各路径最大值（只读，仅 FC3/4；缺失/非数值操作数忽略），路径格式同 sum；用于单元级取最严重模块口径（如过温降载 NTC = 两模块 IGBT 温度取大）。
- `0` 或空：固定值/占位，**不绑定模型**；`dpc set` 可能被下一周期覆盖或无法持久改变物理量。
