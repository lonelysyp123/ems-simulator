# 项目编译与发布说明

说明如何编译 EssSimulator、如何打出可分发的包，以及 `dist/` 产物的布局。

---

## 1. 前置条件

- **.NET 8 SDK**（编译后端）
- **Node 18+**（编译前端；发布脚本会自动 `npm install`）
- Bash（Windows 上可用 Git Bash；开发机为 macOS / Linux 时也可直接跑同一套脚本）

```bash
# 本地调试
dotnet build
dotnet run --project EssSimulator.csproj
dotnet test
```

---

## 2. 前端与后端的关系

- 前端源码在 `Web/`，Vite 的 `build.outDir` 直接指向仓库根 **`wwwroot/`**；
- `dotnet publish` 会把 `wwwroot/` 作为静态站点带进发布目录；
- 因此**发布前必须先构建前端**，三个发布脚本都已内置这一步。

只跑后端（不需要界面）时，可以跳过前端构建，API 与协议端口照常可用。

---

## 3. 发布脚本

三个脚本参数一致，都通过环境变量覆盖：

| 变量 | 默认 | 说明 |
|------|------|------|
| `RID` | 见下 | 目标运行时标识 |
| `CONFIG` | `Release` | 编译配置 |

| 脚本 | 目标 RID | 产物 |
|------|----------|------|
| `scripts/publish-windows.sh` | `win-x64` | `dist/win-x64/`、`dist/EssSimulator-win-x64.zip` |

```bash
./scripts/publish-windows.sh
```

发布目标是 **Windows x64**，采用 **自包含单文件**（`--self-contained` + `PublishSingleFile`），用户机无需安装 .NET 运行时。
脚本本身是 bash，在 macOS / Linux 开发机上同样可以交叉编译出 Windows 包。

### 包内包含什么

每次发布会重新生成输出目录，并放入：

- `EssSimulator`（或 `.exe`）单文件可执行程序；
- `appsettings.json`、`log4net.config`、`autotest.json`；
- `pointmaps/models/`（整棵点表树）；
- `configs/`：`protocol-bindings.json`、`ems-strategy.json`、`topology/`（组态工程与设备库）；
- `docs/`（随包文档）；
- 启动文件：`start.bat`、`README-Windows.txt`；
- 把 `iec61850.dll` 放到可执行文件同目录与 `runtimes/win-x64/native/`。

> **点表说明**：发布始终携带整棵 `pointmaps/models/`。
> **选型型**（`emu` / `bms` / `em` / `pv`）运行期按 `configs/topology/device-models.json` 解析，未选型回退 `{类型}/standard/`；
> **拼装型**（`lc`）：`models/lc/{group,system,unit_5.5MW,unit_10MW,...}/` 为互补片段，按 PCS 组展开后拼装，`unit_5.5MW` 与 `unit_10MW` 始终共存，不是互斥选型。
> `scripts/pointmap-common.sh` 在复制前校验：选型型必须有 `standard/` 及声明文件，LC 每个片段目录必须有 `lc.csv`。

## 4. 自动化发布（GitHub Actions）

`.github/workflows/release.yml`：打 `v*` tag 或手动指定 tag 触发，在 ubuntu 上并行构建三平台包并发布到 Releases。

```bash
git tag v0.2.0 && git push origin v0.2.0
```

流水线会：`npm ci` → 调用 `publish-windows.sh`（内含 `npm run build` + `dotnet publish`）→ 生成 SHA-256 → `gh release create` 挂包。Release 正文模板在 `.github/release-notes.md`。

## 5. dist 目录结构

```
dist/
├── win-x64/                        # publish-windows.sh
└── EssSimulator-win-x64.zip
```

目录里通常含：`EssSimulator.exe`、`appsettings.json`、`pointmaps/models/`、`configs/`、`docs/`、`wwwroot/`、`start.bat`。

`dist/` 已在 `.gitignore` 中忽略，不会进入版本库。

## 8. 维护提示

- 改了 `appsettings.json`、点表或 `configs/` 之后，重新跑一次发布脚本即可（输出目录会整体重建）。
- LC 片段增删只需改 `pointmaps/models/lc/`；发布校验会扫描全部片段的 `lc.csv`，不必再指定点表版本。
- 新增设备型号：在 `pointmaps/models/{设备类型}/{型号}/` 下放点表并在 `model.json` 描述，运行期可在「系统配置」页切换。

## 9. 已知限制

| 限制 | 说明 |
|------|------|
| **Windows 包不启用 GOOSE 订阅** | 随包的 `iec61850.dll` 未编译 GOOSE 订户（没有导出 `GooseSubscriber_*`）。运行期 `Iec61850LayerManager` 会安全降级为"不启用 GOOSE 订阅"并在日志/界面给出原因，**MMS 服务端不受影响**。开发机上的 macOS 原生库带该能力。要恢复 Windows 的 GOOSE 订阅，需在 Windows 上带 GOOSE 支持重新构建 `iec61850.dll`，替换 `lib61850/native/win-x64/iec61850.dll` 后重打包。 |
