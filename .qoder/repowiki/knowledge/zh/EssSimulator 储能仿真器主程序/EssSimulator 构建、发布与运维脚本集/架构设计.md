脚本按职责划分为四个子目录：
- `commercial/`：面向社区版/商业版/定制版/演示版的发布管线，通过 `publish-common.sh` 共享版本解析、运行时拷贝、归档逻辑，再由 `publish-windows.sh` / `publish-linux.sh` / `publish-macos.sh` 按平台分发；`publish-all.sh` 编排三档 × 双平台批量构建，`check-edition-drift.sh` 校验档位差异，`sync-custom-from-root.sh` / `sync-runtime.sh` 维护配置与点位表同步。
- `license/`：基于 HMAC-SHA256 + Base64URL 的私有 license 签发工具（`issue-license.py`），配合 `get-machine-id.{sh,ps1}` 生成机器码，输出 `ESSLIC1.<payload>.<sig>` 格式令牌。
- `test/`：本地集成验证入口，`run-bms-dataexchange-validation.sh` / `run-emu-dataexchange-validation.sh` 自动切换 `appsettings.json`、启动仿真器并调用 `validate-*` 脚本执行 mbpoll 测试，`perf/` 下为性能用例运行脚本。
- 顶层脚本：`dev-up.sh` 一键拉起 dotnet 后端与 Vite 前端（含端口占用检测、进程回收、后端异常重启）；`publish-linux.sh` / `publish-windows.sh` 走自包含 `dotnet publish`；`pointmap-common.sh` 集中定义点位表版本白名单（common/lc/battery）与复制逻辑，被各发布脚本 `source` 复用；`monitor-bms-soc.sh`、`sync-pointmaps-to-root.sh` 为运维辅助。
依赖方向单向：平台脚本 → `pointmap-common.sh` → `pointmaps/` 数据；商业脚本 → `publish-common.sh` → 平台脚本；测试脚本独立于发布管线。
