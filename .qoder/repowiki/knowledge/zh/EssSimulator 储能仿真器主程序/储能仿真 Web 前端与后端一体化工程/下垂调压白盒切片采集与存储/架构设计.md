模块由三个文件构成清晰的三层结构：`DroopSliceModels.cs` 定义不可变的 DTO（`DroopSlice` 及其 `Trigger/Grid/Meter/Pcs/Bms/Topology` 子对象和轻量摘要 `DroopSliceSummary`），作为对外契约；`DroopSliceBuilder.cs` 是纯构造器，通过 `SimulatorHost.Instance.Get` 和 `GuiSimDataAccess` 从仿真运行时按属性路径拉取数据，解析 `serverName` 与 `PcsList[slot]` 目标以计算 channelIndex，并组装为 `DroopSlice`；`DroopSliceStore.cs` 是线程安全的单例式内存环缓冲（`LinkedList<DroopSlice>` + `_gate` 锁），提供 `TryCapture` 入口供 ControlPipeline 在写成功后调用，内部通过 `IsPcsPowerSetting` 过滤仅对 `PCSActivePowerSetting` / `PCSReactivePowerSetting` 触发，并按配置 `WebConfig.DroopSliceCaptureEnabled` 与 `EditionConfig.AllowDroopSlices` 控制功能开关，容量上限 `Math.Clamp` 到 10~5000。依赖方向单向：Store → Builder → Models，且 Builder 依赖外部仿真宿主，不反向引用 Store。
