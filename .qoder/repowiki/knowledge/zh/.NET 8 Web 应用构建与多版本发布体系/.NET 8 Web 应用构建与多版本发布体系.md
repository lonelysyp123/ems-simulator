## 1. 构建系统概览

本项目采用 **ASP.NET Core 8 (Microsoft.NET.Sdk.Web)** 作为统一构建入口，目标框架固定为 `net8.0`，输出类型为独立可执行文件 (`OutputType=Exe`)。前端基于 **Vue 3 + Vite**，通过 `Web/package.json` 管理依赖，构建产物输出到根目录 `wwwroot/`，由 ASP.NET Core 以静态文件形式托管（无需额外反向代理）。

测试使用 **xUnit**（见 `EssSimulator.Tests/`），无显式 test project 配置，默认由 `dotnet test` 发现。

## 2. 核心构建文件

- `EssSimulator.csproj`：主项目定义，声明 `log4net`、`NModbus`、`CsvHelper`、`Microsoft.Extensions.Hosting` 等 NuGet 包；将 `appsettings.json`、`log4net.config`、各 CSV 点位表、`autotest.json` 标记为 `CopyToOutputDirectory=Always` 并 `ExcludeFromSingleFile=true`，确保运行时可被外部替换。
- `Web/vite.config.js`：Vite 配置，开发端口 5173，生产构建输出至 `../wwwroot`，并通过 proxy 将 `/api`、`/hub` 转发至后端（环境变量 `VITE_BACKEND` 控制）。
- `Web/package.json`：定义 `dev`/`build`/`preview` 脚本，依赖 Vue3、Element Plus、ECharts、Three.js、SignalR Client。
- `scripts/dev-up.sh`：开发态一键启动脚本，同时拉起 `dotnet run` 后端与 `npm run dev` 前端，支持 `--backend`/`--frontend`/`--no-open` 模式，自动同步点位表到仓库根目录，并在后端退出时自动重启。

## 3. 发布与打包架构

### 3.1 商业版分档发布
发布体系围绕 `scripts/commercial/` 下的脚本集组织，通过 `EDITION` 环境变量区分三个发行版：
- `社区版` → `configs/社区版.appsettings.json`
- `商业版`（兼容旧名 `充值版`）→ `configs/商业版.appsettings.json`
- `定制版` → `configs/定制版.appsettings.json`

`publish-all.sh` 遍历所有版本，分别调用 `publish-windows.sh` / `publish-linux.sh`，最终产物布局为 `dist/<Edition>/<RID>/`，顶层生成 `EssSimulator-<Edition>-<RID>.zip` 或 `.tar.gz`。

### 3.2 平台发布脚本
- `publish-linux.sh`：调用 `dotnet publish -c Release -r linux-arm64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true`，然后复制运行时配置文件、点表、文档，并生成 tar.gz。
- `publish-windows.ps1`：Windows 下使用 `win-x64` RID，启用 `EnableCompressionInSingleFile=true`，通过 `Compress-Archive` 打包 zip。
- `publish-common.sh`：提供公共函数 `copy_runtime_files`（复制 appsettings.json、log4net.config、autotest.json、pointmaps）、`copy_platform_files`（按平台拷贝 start.bat/start.sh 及说明）、`create_zip_archive`/`create_tar_archive`。

### 3.3 运行时资源
发布产物包含：
- 单文件可执行程序 `EssSimulator`
- 运行时配置文件 `appsettings.json`（来自对应 Edition 的 configs/）
- `log4net.config`、`autotest.json`
- 点位表 CSV（通过 `pointmap-common.sh` 按版本复制到输出目录）
- 平台特定启动脚本（Linux/macOS: `start.sh`；Windows: `start.bat`）
- 可选 `docs/` 目录

## 4. 开发与部署约定

- **开发环境**：`./scripts/dev-up.sh` 是标准入口，自动安装前端依赖、同步点位表、启动前后端，监听 HTTP_PORT=5050（后端）和 VITE_PORT=5173（前端）。后端通过 `Simulator__Web__HttpPort` 覆盖配置端口。
- **运行环境**：Linux/macOS 使用 `scripts/linux/start.sh` 启动，自动尝试打开浏览器；Windows 使用 `scripts/windows/start.bat`。
- **点位表管理**：CSV 点位表位于 `pointmaps/` 下按版本（common/lc/battery 等）划分，通过 `scripts/sync-pointmaps-to-root.sh` 同步到根目录供 `dotnet run` 直接读取；发布时由 `pointmap-common.sh` 指定版本复制。
- **自包含发布**：所有平台均使用 `--self-contained true` 和 `PublishSingleFile=true`，将依赖打包进单个可执行文件，但排除 `appsettings.json`、`log4net.config`、CSV 等运行时可替换资源。
- **前端构建集成**：`Microsoft.NET.Sdk.Web` 默认将 `wwwroot/` 作为静态文件目录，因此只需先运行 `vite build` 即可将前端产物纳入发布；开发阶段通过 Vite HMR 单独服务。

## 5. 约束与规则

- 版本号通过 `EDITION` 环境变量驱动，仅允许 `社区版`、`商业版`（含旧别名 `充值版`）、`定制版` 三种。
- Linux 发布默认 RID 为 `linux-arm64`，可通过 `RID` 环境变量覆盖。
- 发布配置必须存在于 `configs/<Edition>.appsettings.json`，否则脚本报错退出。
- 开发启动前若根目录缺少 `emu.csv` 等点位表，会强制调用 `sync-pointmaps-to-root.sh` 同步，否则 Modbus 从站无法启动。
- 前端依赖通过 `node_modules` 缓存，首次运行 `dev-up.sh` 会自动执行 `npm install`。
- 测试项目通过 `<InternalsVisibleTo Include="EssSimulator.Tests" />` 暴露内部类型给测试程序集。
