## 1. 使用的系统/工具

本仓库是 C#/.NET Web 应用（ASP.NET Core），同时内置 Vue3 前端工程。依赖管理采用**双栈**：

- **后端 (.NET)**：使用 `Microsoft.NET.Sdk.Web` SDK 的包管理，通过 `.csproj` 中的 `<PackageReference>` 引用 NuGet 包；无 `packages.config`、无 `global.json`、无 `NuGet.config`，默认使用 nuget.org。
- **前端 (Web/)**：使用 `npm` + `vite`，通过 `package.json` 声明依赖，并通过 `package-lock.json` 锁定精确版本。

## 2. 关键文件

| 文件 | 作用 |
|---|---|
| `EssSimulator.csproj` | 后端唯一依赖清单，定义 TargetFramework `net8.0` 及全部 NuGet 包引用 |
| `EssSimulator.Tests/EssSimulator.Tests.csproj` | 测试项目，通过 `<ProjectReference Include="..\EssSimulator.csproj" />` 引用主项目，并声明 xUnit、Test SDK 等测试依赖 |
| `Web/package.json` | 前端依赖清单（Vue3、Element Plus、ECharts、Three.js、SignalR Client 等） |
| `Web/package-lock.json` | npm 锁文件，锁定所有依赖树的确切版本与 sha512 校验和 |
| `wwwroot/` | ASP.NET Core 静态文件目录，由构建流程将 `Web/dist/` 产物复制至此，作为运行时前端资源 |

## 3. 架构与约定

### 3.1 .NET 后端依赖

- **目标框架**：`net8.0`，输出类型为 `Exe`（可执行程序）。
- **显式引用的第三方包**（均在 `EssSimulator.csproj` 中声明）：
  - `log4net 2.0.17`：日志框架。
  - `Microsoft.Win32.Registry 5.0.0`：读取 Windows 注册表（用于机器 ID 授权）。
  - `NModbus 3.0.81`：Modbus TCP 从站实现。
  - `CsvHelper 32.0.0`：CSV 点位表解析。
  - `Microsoft.Extensions.Hosting 8.0.1`：宿主服务框架。
- **隐式提供的包**：注释明确说明“ASP.NET Core / SignalR Server 由 Microsoft.NET.Sdk.Web 隐式提供，无需显式引用”。这意味着 Web 功能（Kestrel、SignalR Server、静态文件托管）来自 SDK 的隐式包引用。
- **内部可见性**：通过 `<InternalsVisibleTo Include="EssSimulator.Tests" />` 暴露内部成员给单元测试项目。
- **排除项**：`DefaultItemExcludes` 排除了 `dist/**`、`bin/**`、`obj/**`，避免发布时把构建中间产物当作源文件复制。

### 3.2 前端依赖

- **运行时依赖**：`vue 3.4.x`、`vue-router 4.3.x`、`element-plus 2.7.x`、`echarts 5.5.x`、`three 0.170.x`、`axios 1.7.x`、`@microsoft/signalr 8.0.x`。
- **开发依赖**：`vite 5.2.x`、`@vitejs/plugin-vue 5.0.x`。
- **版本策略**：全部使用 `^` 语义化版本范围，但通过 `package-lock.json` 锁定实际安装版本，保证构建可重现。
- **构建产物**：`vite build` 输出到 `Web/dist/`，再由 MSBuild 复制到 `wwwroot/` 供 ASP.NET Core 静态文件服务托管（见 csproj 注释：“前端构建产物由 Microsoft.NET.Sdk.Web 默认作为 wwwroot 静态文件托管”）。

### 3.3 项目间依赖

- 仅有一个 `ProjectReference`：`EssSimulator.Tests` → `EssSimulator`。
- 其他模块（如 `EssDeviceSimModel`、`EssSimModelApi`、`Protocol`、`LocalControl` 等）在代码中以命名空间形式组织，但**未拆分为独立的 .csproj**，因此不存在跨项目引用关系——整个后端是一个单体项目。

## 4. 约定与约束

- **NuGet 包版本固定**：每个 `<PackageReference>` 都写死了具体版本号（如 `NModbus 3.0.81`、`CsvHelper 32.0.0`），没有使用 `*` 或浮动版本，便于复现。
- **无私有 NuGet 源**：仓库根未发现 `NuGet.config`，推断直接使用 nuget.org。
- **无 vendoring**：未使用 dotnet pack 的 `PackageVersion` 覆盖或 vendor 目录方式；依赖由 NuGet 缓存管理。
- **前端锁文件受控**：`Web/package-lock.json` 提交到版本库，确保 CI/本地构建得到一致的前端依赖树。
- **前端产物不纳入源码**：`wwwroot/assets/*` 为构建产物（带 hash 的文件名），但 `Web/src/` 源码才是依赖来源；`.gitignore` 应忽略 `node_modules/` 和 `dist/`。
- **测试依赖隔离**：xUnit、coverlet、Test SDK 仅在 `EssSimulator.Tests.csproj` 中声明，不影响生产包大小。
- **运行时配置外置**：`appsettings.json`、`log4net.config` 通过 `<None Update ... CopyToOutputDirectory="Always">` 复制到输出目录，且 `ExcludeFromSingleFile=true`，表明部署时这些配置文件需独立存在，不可被单文件发布打包进 exe。
